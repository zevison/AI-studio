===== V3.4.2_更新说明.txt =====
Seedance Studio V3.4.2｜视频编辑修复与 OSS 持久化完整整合版

一、修复爆款复刻失败
- 爆款复刻现在明确采用 Seedance 视频编辑语义。
- API 请求固定：
  ratio = adaptive
  duration = -1
  输出时长继承原视频
- 原视频实际时长只作为本地历史 / 费用参考，不再错误地四舍五入后传给 duration。
- 在任何付费 POST 之前新增本地参数自检：
  1) 必须为 video_mode=edit
  2) duration 必须为 -1
  3) ratio 必须为 adaptive
  4) 必须存在有效参考视频
  5) 必须读取到有效原视频时长
- 任一项失败都在本地拦截，不调用 Seedance 付费创建接口。

二、费用显示更诚实
- 如果没有配置可靠的本地参考单价，不再给出假精确金额。
- 预览会显示：
  爆款复刻（视频编辑）
  输出时长继承原视频
  本地计费参考时长
  当前 OpenLux 路由目标
  调用次数
- 成功率最高路由并不等于价格最低；实际账单仍以 OpenLux 后台为准。

三、阿里云 OSS 配置跨版本持久化
- Windows 下新增稳定配置目录：
  %LOCALAPPDATA%\SeedanceStudio
- 非敏感 OSS 配置保存到 profile.json。
- OSS AccessKey 保存到独立 secrets.json。
- 第一次启动会尝试从当前版本或同目录旧版本自动迁移 OSS 设置。
- 从此版本开始，后续升级不需要重复输入 OSS Endpoint、Bucket、AccessKey。
- “恢复推荐默认值”不会再清掉 OSS 基础设施配置。
- 可继续通过设置页主动清除 OSS 凭据。

四、保留
- V3.4.1 静默本地分析
- 结果导向爆款复刻
- 10 个全局视频并发
- SQLite 任务持久化 / 刷新恢复
- 创建接口 0 次自动重试
- OSS 临时签名链接

===== V3.6.2_更新说明.txt =====
Seedance Studio V3.6.2｜@真实绑定校验完整整合版

这版不是只优化 @ 选择器，而是修正 @ 引用与 Seedance 实际 API 输入的对应关系。

核心修复：
1. @图片N / @视频N / @音频N 现在严格按“当前实际提交的同类型素材顺序”连续编号。
2. 后端发送给 Seedance 前，把 UI 中文别名转换成官方提示词引用：@imageN / @videoN / @audioN。
3. 用户提示词引用不存在素材时，本地直接阻止预览，不进入付费创建。
4. 删除前面的素材后，会自动重写剩余素材的 @编号；被删除的引用改成“已删除素材”提示，避免错绑到别的文件。
5. 首帧 / 首尾帧不再通过重排素材实现。现在保持原始内容顺序不变，通过 content.role=first_frame / last_frame 绑定，所以 @编号不会错位。
6. 未写首尾帧规则时：第 1 张图片=首帧，第 2 张图片=尾帧。

===== V3.7.6_更新说明.txt =====
Seedance Studio V3.7.6｜视频单次提交原子锁完整整合版

【为什么 V3.7.5 偶尔会让同一个指令生成两条视频】
后台使用 ThreadingHTTPServer，同一时间可以进入多个 HTTP 请求。

旧逻辑把下面这些步骤拆成了多个独立数据库操作：
1. 检查确认令牌是否使用
2. 检查相同 fingerprint 是否已有任务
3. 检查 10 并发
4. 标记确认令牌 consumed_at
5. 创建本地 task
6. 调用 OpenLux 付费创建

两个请求如果几乎同时进入，可能都在步骤 1～3 看见“还没有任务”，
于是都继续执行到第 6 步，造成同一个指令出现两条平台视频。

【V3.7.6 修复】
新增 SQLite 数据库级原子提交锁：
db.claim_video_submission()

一个 BEGIN IMMEDIATE 事务内完成：
- 确认令牌读取
- 同 fingerprint 活跃任务检查
- dedupe 时间窗检查
- 10 并发检查
- consumed_at CAS 占用
- 唯一本地 pending task 创建

只有 state=claimed 的请求才允许进入 OpenLux POST。

保护范围：
- 快速双击
- 浏览器重复事件
- 同一页面重复请求
- 多标签页
- 后台多线程
- 同一数据库上的多进程竞争
- 两个不同 preview token 但 fingerprint 完全相同
- 9/10 并发时两个请求同时进入导致 11/10

同时保留：
- PAID_CREATE_RETRIES=0，付费创建永不自动重试
- Idempotency-Key=fingerprint
- submission_unknown 不自动重提
