日期：2026-10-16，Windows 本机。**研发检查点，不是完整集成完成证明，不是稳定版。**

## 结论与边界

已完成真实官方 SDK Endpoint 的编译、安装式 Runtime 激活和离线生命周期调度；真实 OpenLux LLM 读取官方 Skill，通过 tools 写出两个不同剪裁工程，官方 Runtime 在本机成功生成 1 秒及 3 秒 MP4。没有调用付费视频、图片或音频生成接口。

**原 Seedance 网页的官方 Agent 接线尚未合并。** 原应用继续保留 V5.0.0 的业务界面与功能；新增源码和 Provider 位于隔离开发树，开发补丁只安装基础模块与依赖包，不会把原有“爆款复刻”按钮伪装为已完成官方 Agent。V5.1.1 候选中固定 15 秒编排与未经验收的 UI/Provider 逻辑没有整体覆盖进来。

仍待完成：参考编辑/延长/动作迁移的账号协议与素材字段实证、视频报价及授权、实际视频任务恢复、业务级参考理解与商品一致性验证，以及阶段 E 的 UI、统一任务中心与成本中心合并。新的自定义组件/可执行项目包暂不向 Agent 开放，须先建立独立代码审查和执行隔离边界。

## 费用与真实接口

用户明确授权：仅 LLM tools/工程编写，最多 US$0.50、总计 4 次调用、每次至多 2048 输出 Token。视频生成始终未授权、未调用。

只读 `/v1/models` 返回 334 个模型，包含目标 Seedance 2.5；这只证明目录成员关系。只读 `/api/pricing`、`/api/status`、账号分组确认 USD、500000 quota/USD 与当前账号可用分组倍率。视频行的 `model_price=0.01` 缺少完整规格口径，**没有当作真实视频任务报价**。

实际使用 `gpt-6-luna`。首个请求被明确 HTTP 400 拒绝；只读日志确认 quota=0、Token=0，原因是 tools 需要 `reasoning_effort=none`。保留该调用次数和 US$0.125 预占后，在剩余三次调用中完成两份源码创作。最终已用完四次调用额度，禁止自动追加调用。

三条成功账单的 Token 数与三个成功响应逐一匹配；总计 669 quota，按服务端当次 500000 quota/USD 口径为 **US$0.001338**。这是账号返回的计费记录，区别于预检参考费率。详见 `live-agent-results.json` 和 `llm-reconciliation.json`。

探索性 continuation 在预算哈希之后补加了 reasoning 参数；交付的正式模块已修正为先设置协议参数，再计算预算和请求指纹，并有“实际 wire bytes = ledger hash”回归。没有为此追加第五次在线调用。

## 红队审查与修复

1. **重复扣费与恢复**：远端接收后丢失回执、并发重复 start、进程重开、提交超时均注入测试；预先持久预占，未知状态隔离，不能自动重发。未知模型/媒体字段/远端状态拒绝；取消未验证时返回 unsupported，不能冒充远端已取消。
2. **SSRF / 路径 / 密钥**：旧下载器“查 DNS 后再重新解析”存在重绑定窗口。默认下载器现直接连接已核实公网 IP，并保留原 hostname 的 TLS SNI/证书校验，拒绝重定向、混合私网 DNS、错误 MIME、截断长度和超限文件。Agent 拒绝 NTFS ADS、保留设备名、junction 逃逸、外部编译资源、未审查项目包与 CSS 外部加载；素材替换会使付费工程指纹失效。
3. **Windows 数据与安装**：修复 sqlite3 上下文不自动 close 导致的备份文件占用；升级中断、未知本地修改、已有活动任务、重复安装和回滚均测试。回滚仅恢复代码，不倒退用户新任务数据库。
4. **供应链**：初次 npm 审计的 55 条受影响记录来自 sharp 与 esbuild 两个根因及其依赖链，非 55 个独立漏洞。固定 sharp 0.35.5、esbuild 0.28.1 后审计归零。上游精确依赖声明会拒绝安全升级版本，因此增加仅修改三份依赖 manifest 的可复现哈希补丁，官方执行源码未修改；已重新通过真实 Runtime 和本地媒体流程。

安全公告：[sharp / librsvg](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)、[esbuild Windows 开发服务器](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr)。sharp 公告描述的 RCE 条件主要涉及特定 glibc Linux 环境；本次仍统一修复依赖。
